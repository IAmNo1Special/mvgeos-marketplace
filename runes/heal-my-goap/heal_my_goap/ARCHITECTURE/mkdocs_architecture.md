## 2. Design Principles

### 2.1 Information Architecture — "3-Click Rule"

Every piece of information is reachable in ≤3 clicks from the homepage. The site is organized into **4 top-level navigation tabs** plus a **Home** landing page, each mapping to a distinct user intent:

| Tab | Intent | Audience |
| :--- | :--- | :--- |
| **Home** | "What is this and should I care?" | First-time visitors, evaluators |
| **Getting Started** | "I want to install and understand" | New users adopting the library |
| **User Guide** | "I want to build something" | Active developers integrating features |
| **Examples** | "Show me working code" | All users, especially copy-paste learners |
| **API Reference** | "I need the exact signature" | Experienced users, AI coding agents |

### 2.2 User Journeys

**First-time visitor** (evaluator):
```
Home (hero + feature cards + quickstart)
  → Getting Started > Installation (30 seconds to install)
    → Getting Started > Core Concepts (understand the architecture)
      → Examples > Coding Agent (see it in action)
```

**Returning developer** (building a feature):
```
User Guide > Tool Registration (how to register my tools)
  → API Reference > GoapEngine (exact constructor signature)
```

**AI coding agent** (programmatic consumption):
```
/llms.txt (discover API surface)
  → API Reference > Models & Helpers (import paths, parameter types)
    → Examples > System Monitor (working code pattern to adapt)
```

### 2.3 Recommended Reading Order (Home Page)

The Home page includes a "New here?" tip admonition with a guided reading order for first-time visitors:

```markdown
!!! tip "New here? Recommended reading order"
    1. [Installation](getting-started/installation.md) — Get set up in 30 seconds
    2. [Core Concepts](getting-started/concepts.md) — Understand GOAP, gaps, and self-healing
    3. [Coding Agent Example](examples/coding-agent.md) — See a full 8-step autonomous pipeline
    4. [Tool Registration](user-guide/tool-ingestion.md) — Register your own tools
```

This provides a clear "golden path" without requiring users to discover the right order themselves.

### 2.4 Progressive Disclosure

Each section follows a depth funnel — users land on an overview and drill down only as deep as they need:

```
Section Index Page (overview + navigation cards to child pages)
    → Conceptual Page (what it is and why it matters)
        → Guide Page (step-by-step how-to with annotated code)
            → API Reference (exact signatures, parameters, return types, defaults)
```

### 2.5 Scannability

Every content page follows a predictable structure so users can orient themselves within 5 seconds:

1. **Frontmatter** — `title` and `description` for SEO and AI agents
2. **Page heading** — `<h1>` with concise title
3. **"At a Glance" admonition** — 2-3 sentence summary of the key takeaway
4. **Body content** — Explanations, diagrams, annotated code (target: 3-7 minute read)
5. **Related pages** — Cross-links to relevant guides or API reference at the bottom

### 2.6 AI / Coding Agent Friendliness

Documentation should be as useful to an AI agent reading it programmatically as to a human browsing it visually:

| Pattern | Implementation | Why |
| :--- | :--- | :--- |
| **Structured headings** | Strict `h1 > h2 > h3` hierarchy, never skipping levels | Agents parse heading trees to build context |
| **Semantic code blocks** | All code blocks have language tags (`python`, `bash`, `yaml`) | Agents identify language for code generation |
| **Copy-friendly code** | `content.code.copy` enabled; no line numbers in copyable blocks | Agents and humans paste directly |
| **Code annotations** | `content.code.annotate` with numbered callouts | Agents extract inline explanations |
| **Clean URL slugs** | `/user-guide/tool-ingestion/` not `.html` | Predictable URLs for programmatic access |
| **`llms.txt`** | Machine-readable site summary with module list and doc links | AI agent site discovery convention |
| **`sitemap.xml`** | Auto-generated by MkDocs | Crawlers and agents enumerate all pages |
| **`robots.txt`** | Permits all crawlers, references sitemap | Standard crawler discovery |
| **Frontmatter metadata** | `title` and `description` on every page | Agents extract page purpose without parsing body |
| **Structured parameter tables** | API ref pages use tables with columns: Parameter, Type, Default, Description | Agents extract structured data directly |
| **Consistent naming** | API ref headings match Python import paths | `from heal_my_goap import X` maps to `/api-reference/models/` |

### 2.7 Visual Design — "Dark-First Premium"

The site defaults to **slate (dark) mode** with a one-click light mode toggle. The visual language communicates "modern developer tool" — not "generic docs template."

## 7. Deployment — GitHub Actions

### 7.1 Workflow: `.github/workflows/docs.yml`

```yaml
name: Deploy Documentation

on:
  push:
    branches: [main]
    paths:
      - 'docs/**'
      - 'mkdocs.yml'
  workflow_dispatch:

permissions:
  contents: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0          # Full history for git revision dates

      - name: Install uv
        uses: astral-sh/setup-uv@v5

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.13'

      - name: Install dependencies
        run: uv pip install --system mkdocs-material pymdown-extensions

      - name: Validate build (strict mode)
        run: mkdocs build --strict

      - name: Deploy to GitHub Pages
        run: mkdocs gh-deploy --force
```

### 7.2 Key CI/CD Design Decisions

| Decision | Rationale |
| :--- | :--- |
| `paths` filter on `docs/**` and `mkdocs.yml` | Only rebuild docs when docs content changes, not on source code changes |
| `uv pip install --system` | Uses `uv` for fast installs, consistent with project tooling |
| `mkdocs build --strict` as separate step | Catches broken links and warnings before deploy — fails the build if any issues |
| `fetch-depth: 0` | Full git history enables future git-revision-date plugin support |
| `workflow_dispatch` | Allows manual re-deployment from GitHub UI |

### 7.3 Repository Settings Required

1. **Settings → Pages → Source**: `Deploy from a branch`
2. **Settings → Pages → Branch**: `gh-pages` / `/ (root)`

## 8. CSS Architecture

### 8.1 Stylesheet Organization: `docs/stylesheets/extra.css`

| Section | Responsibility |
| :--- | :--- |
| **1. CSS Custom Properties** | Override Material theme `--md-*` tokens for both `slate` and `default` schemes |
| **2. Hero Banner** | Gradient background, glassmorphism border, gradient text on `h1`, CTA buttons |
| **3. Feature Grid Cards** | CSS Grid `auto-fit` layout with hover lift/glow transitions |
| **4. Code Blocks** | Border, border-radius, box-shadow enhancements |
| **5. Admonitions** | Rounded corners and deeper box-shadows |
| **6. Custom Scrollbar** | Slim 8px track with indigo hover highlight (WebKit) |
| **7. Focus Rings** | `2px solid #6366f1` with `2px offset` for keyboard navigation |
| **8. Reduced Motion** | `@media (prefers-reduced-motion: reduce)` disables hover transforms and transitions |
| **9. Responsive Breakpoints** | Card grid → single column below `600px`; hero font scales down below `768px` |

### 8.2 Reduced Motion Support

```css
@media (prefers-reduced-motion: reduce) {
  .grid.cards > div {
    transition: none;
  }
  .grid.cards > div:hover {
    transform: none;
  }
  .hero-banner {
    animation: none;
  }
}
```

### 8.3 Design Token Strategy

All colors are defined as `--md-*` CSS custom properties scoped to `[data-md-color-scheme="slate"]` (dark) and `[data-md-color-scheme="default"]` (light). This ensures:

- The entire palette is updatable from a single location
- Light mode has its own explicit tokens (not just "inherited defaults")
- Material theme components (admonitions, search, nav) automatically consume our tokens
